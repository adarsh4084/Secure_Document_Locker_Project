AES-256-GCM file encryption

Every file receives a fresh random data key and a unique nonce. GCM authenticates encrypted content so tampering is detected when the file is opened.

Password-protected vault key

A key derived from the account password wraps the random vault key. The application verifies the password before unlocking that key at sign-in.

PBKDF2-HMAC-SHA256
03

Separate six-digit PIN

The PIN is stored as a salted Scrypt hash. Failed PIN checks are rate-limited, with a temporary lock after repeated errors.

SALT + SCRYPT + LOCKOUT
04
◷

Session and form protection

The browser receives a signed session token, while vault key material is kept server-side in an encrypted session record. Forms use CSRF tokens and sessions expire.

HTTPONLY COOKIE + CSRF

Activity history

Successful actions and important security events are recorded with a timestamp and a short description, without recording passwords, PINs, or file content.

Local storage by default

Encrypted file blobs are stored under the local instance folder, while SQLite stores metadata and encrypted key material. No third-party cloud is required.

Important before using real sensitive files

This is a learning project, not a formally audited vault. Keep the app secret key safe, use HTTPS in deployment, restrict operating-system access to the instance folder, protect backups, add a secure recovery process, and have the code independently reviewed before storing real financial, identity, or medical records.
